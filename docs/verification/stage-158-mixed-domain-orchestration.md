# 第 158 阶段：混合域拆分与独立降级

日期：2026-08-11

## 阶段目标

解决百题独立验收中混合题的两个根因：产品事实与售前治理被压入单一知识域，以及任一知识域失败会取消兄弟域并让整题失败。本阶段不修改冻结百题集，也不修改两个知识库。

## 实施内容

- 扩展产品中立治理信号，覆盖成功指标、退出条件、责任人、基线、测量周期、采购决策、RACI、TCO、截止时间等通用治理义务。
- 当整题明确同时包含产品事实和治理目标时，确保最终 TaskSpec 至少覆盖 `coremail-professional` 与 `presales-general` 两个域，避免模型把另一半请求压丢。
- 收紧实体列表抽取边界，避免把“检索与导出能力”或“TCO 维度”误识别为并列实体。
- 两个域独立执行，不再因一个域失败主动取消兄弟域。
- 单域成功时保留已核验结果，失败域生成 `tool_unavailable` 覆盖缺口并输出部分回答；两个域都失败时仍返回暂时不可用。
- 已绑定答案卡发布版本发生快照漂移时继续整题失败，不允许以部分回答绕过发布完整性边界。
- 负载探针支持从外部矩阵按题号读取，并记录 TaskSpec 域数、守卫、激活、引用域和缺口数。
