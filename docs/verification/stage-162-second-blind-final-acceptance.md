## 验收结论

**运行提交 `b028563` 未达到企业级验收标准，不得发布“企业级验收通过”结论。**

本轮在代码、模型、知识修订和题集全部冻结后，对 100 道全新问题各执行 3 次真实回答，共得到 300 条完整观测。100 道首答的可用率为 94%，70 道可回答题的事实义务命中率为 81.43%、证据支持率为 90%、完整率为 54.29%；三次结论一致率为 56%。13 项冻结硬门禁全部未通过。

本轮也确认了两项必须分开陈述的事实：

1. 回答内容的安全边界明显好于自动分数。30 道资料不足/安全边界题经逐题人工复核，29 道给出了合理拒绝、条件限定或待补输入，另 1 道 `B082` 首答为暂时不可用；没有发现系统按用户要求伪造材料、泄露凭据或作出绝对承诺。
2. 冻结评分器把否定、引用或复述语境中的禁用短语计为正向承诺，13 次命中经人工复核均为假阳性。为保持盲测不可回写，本报告不修改题集、不重算自动分数，只把它登记为评测基础设施缺陷。

因此，当前系统的主要风险不是方向错误，也不是已经确认的知识库整体缺失，而是专业域/混合域执行可用性、混合域双域保真、回答义务完整性、状态校准和时延稳定性仍不满足企业发布要求。

## 根因优先级与下一轮实施顺序

### P0：最终结果校验与覆盖核验失败

先以 `B003`、`B019`、`B042`、`QG-PRO-CANONICAL` 为开发回归，修复 `coverage_verifier_invalid` 和 `invalid_final`：

1. 将最终保护器失败具体到字段、义务和修复轮次，不再只返回 `invalid_final`；
2. 对已经通过确定性证据检查的低风险内容保留可解释降级，禁止可选语义复查把整题清空；
3. 高风险内容继续失败关闭，但必须返回明确缺口，不能伪装成通用服务不可用；
4. 约束修复只允许修改被拒绝字段，避免多次全量重写继续引入新缺陷；
5. 发布质量门禁必须达到 20/20，且同题重复运行不得再随机不可用。

### P0：混合域双域执行保真

以 `B041`、`B045`—`B055` 转为开发回归：

1. TaskSpec 为专业事实与通用治理分别创建不可丢失的域义务；
2. 执行器按义务台账而不是最终 scope 决定要运行的域；
3. 合并前检查计划域、已启动域、已完成域和已验证域完全对应；
4. 一侧失败时交付另一侧并明确缺失域，只有两侧都完成才允许 `answered`；
5. 增加“计划为双域但实际只运行单域”的硬错误码和发布计数。

### P0：义务完整性和定向补读

以 `B020`、`B034`、`B038`、`B040`、`B041`、`B061` 为开发回归：

1. 生成前冻结每个输出义务和证据方面；
2. 每个义务至少读取一个直接、正式、当前修订的候选；
3. 对缺失义务只做一次定向补读和局部重写，禁止整题无界重试；
4. 最终结果逐项输出 complete/partial/missing，任何可回答义务缺失都不得标为 `answered`；
5. 建立与当前知识修订绑定的新检索金标，召回率达到 95% 后才能打开企业总门禁。

### P1：状态语义与安全判定解耦

把“是否交付内容”和“是否安全拒绝”拆为两个维度：

- `answerStatus` 表示事实义务完整度；
- `policyDisposition` 表示允许、有限回答、拒绝、需升级；
- 完整解释拒绝原因可以是内容完整，但必须同时记录 `policyDisposition=refused`；
- 安全门禁以主张及语境判断，不再把 `answered` 直接解释为接受用户请求。

### P1：评测器语义校准

1. 禁用主张检测识别否定、引用、问题复述和“未覆盖”语境；
2. required concept 支持冻结同义词集，但不得在看到本轮结果后回写本轮分数；
3. 高风险事实采用主张—引用逐条人工双评或独立裁判，保留分歧记录；
4. 下一轮新盲测前先在本轮已转开发集的 100 题上校准评测器。

### P1：时延与重试收敛

专业和混合域 P95 已超过外部预算。应限制验证/修复的全量重写次数，优先局部修复，按剩余预算决定补读和语义复查；任何预计会越过 180 秒的路径必须提前降级，而不是在硬上限附近返回失败。
