## 基线与根因

最初用不等同于生产回答链路的纯词法检索得到 44/60，这次结果仅用于发现运行方式错误，不作为产品基线。改为回答链路实际使用的混合检索后，原实现为 55/60：专业域 25/30，通用域 30/30。

剩余缺陷集中在两类：

1. 图扩展使用固定配额，会把已经进入前十的直接词法命中挤出结果，而不是只补足空位。
2. 含英文产品名的直接标题和明确对比页权重不足，正文中偶然出现相同词的宽泛页面可能排在目标页面之前。

## 实施变更

- 图邻居只填充直接检索未占满的 `topK` 空位，不再无条件挤出直接命中。
- 对标题中的显著拉丁字母/数字产品词增加确定性权重。
- 只有查询具有明确对比意图、页面类型为对比页、标题实际包含对比主体且存在最低覆盖时，才增加对比页权重；宽泛或无关对比页不会获得该加权。
- 为上述三个边界增加 Rust 回归测试，并为题集解析、双域硬门禁、可用性和修订漂移增加 TypeScript 契约测试。

隔离候选引擎上的提交前同源验证为 59/60（98.3333%）：专业域 29/30（96.6667%），通用域 30/30（100%），可用率 100%。唯一未召回的是 `RG001`；其前十均为更具体的 Coremail/Exchange 相关直接资料，因此保留为真实失败，不修改题目或目标路径凑分。
