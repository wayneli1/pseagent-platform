# 阶段 170：混合域识别与执行泛化

## 结论

第二套全新百题暴露的混合域路由缺陷已完成第一阶段收敛。原验收中，15 道混合题首轮仅 3 道实际同时使用专业库与通用售前库；修复后的开发回归为 **15/15** 使用双域，且 **15/15** 均返回可用结果。

本阶段结果只证明已知缺陷得到泛化修复，不作为新的独立验收成绩。`enterprise-blind-acceptance-20260811-final.json` 自首次运行后已转为开发集，最终结论仍必须使用第三套、先封存后运行的全新百题。

## 根因与修复

1. 模型生成的 `TaskSpec` 可能把“技术事实/证据 + 售前治理方法”压缩成单一知识域。
2. 高置信答案卡族可能进一步把混合任务缩成一张专业卡覆盖的单域任务。
3. 现有确定性识别词表没有覆盖日志、队列、证书、OAuth2、DMZ、全文索引、多活切换等长尾技术锚点，也没有覆盖证据门、小承诺、角色责任、四栏记录、透明边界、黄灯对话等治理目标。

实施内容：

- 增加 `requiresMixedKnowledgeDomains`，用“明确技术证据目标 + 明确治理交付物”共同判定混合域，不依赖某一道题的完整句式。
- 在任务分析完成、答案卡适配结束后，再做一次确定性双域修复；只有多域执行开关已启用时才生效，避免改变单域兼容路径。
- 禁止单张高置信答案卡族把明确混合请求编译为单域任务。
- 为 15 种新的技术/治理组合增加表驱动回归，并增加答案卡压缩和服务级真实执行边界测试。
- 新增 `probe:mixed-domain-development`，明确标注为开发回归，只检查双域执行与可用性，不复用为盲测验收器。
