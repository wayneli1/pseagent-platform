# 阶段 181：共享动作义务收敛

## 结论

第五套冷验收暴露的部分完整度问题并非单纯由生成模型漏答造成。确定性任务链会把一个共享动作下的并列维度拆成多个残缺事实义务，同时把场景前提和否定约束当作必答项。修复后，完整方法请求优先于其内部语义碎片；真正独立的连续动作仍保持独立。

第五套验收结果不变：它已经失败并转为开发集，本阶段的选择性重跑只用于缺陷验证，不作为新的盲测成绩。

## 已确认根因

1. “只覆盖一个联系人”被显式请求提取器误识别为“要求覆盖”的并列清单。
2. 完整请求与语义原子相交时，契约编译器保留短原子并丢弃完整请求。
3. 位于首个明确请求之前的场景前提被生成了事实义务。
4. “而不是回避价格”等尾随约束被生成了独立事实义务。
5. “方案能力”等词出现在方法转换问题中时，直接事实关键词优先级过高，导致方法义务被错误标记为 `direct`。

## 实施结果

- 现状型“只覆盖/仅覆盖/已覆盖/未覆盖/不覆盖”不再进入要求覆盖清单。
- 一个明确请求覆盖多个语义原子或未决片段时，使用可追溯的完整请求跨度替换内部碎片。
- 存在明确请求时，删除其之前仅用于描述场景的语义原子。
- 否定性尾随约束不再成为独立回答标题。
- 共享转换方法和有序连续动作确定性归类为 `procedure + synthesis`。
- 真正的并列必答项、独立请求及混合域联合执行规则保持不变。
