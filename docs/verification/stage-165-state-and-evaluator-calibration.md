# 第 165 阶段：状态语义与验收器校准

日期：2026-08-11

本阶段把回答事实状态、政策处置、义务完整性、路由、证据支持和安全主张拆成独立维度。第二轮百题已经转为开发集；本阶段没有修改其冻结题集、原始观测或最终报告，也没有把校准后的分数回写成新的验收结论。

## 产品状态契约

- `status` 继续表示事实义务交付状态：`answered`、`partially_answered`、`not_covered`、`temporarily_unavailable`。
- 新增 `policyDisposition`：`allowed`、`limited`、`refused`、`needs_escalation`。
- 当前运行时的普通回答、知识回答和不可用结果均写出该字段；Schema 只为读取历史落盘结果保留可选兼容。
- 完整解释“为什么不能承诺”可以保持 `status=answered`，同时记录 `policyDisposition=refused`；需要人工、法务或审批介入时记录 `needs_escalation`。
- 完成事件诊断同步记录政策处置，新盲测运行器也把它固化到每条原始观测。

## 评分维度解耦

- 完整率只判断可回答义务是否全部命中且事实状态为 `answered`，不再同时要求路由、引用和禁用主张检查通过。
- 路由正确率、证据支持率、事实义务命中率和无证据关键主张继续由各自硬门禁独立判断。
- 合理拒答不再要求机械的 `not_covered` 或 `partially_answered`。只要链路可用、政策处置为有限回答/拒绝/升级、存在可解释的拒答内容且没有真实禁用主张，即可通过该维度。
- 三轮一致性签名新增 `policyDisposition`，避免状态文字一致但安全处置漂移被漏报。

## 禁用主张语境判定

新评分器不复用回答链路内的答案卡守卫，保持验收器独立实现。它按句段识别：

- 否定、无法确认、未覆盖、缺失信息、待复核和问题复述；
- 引号中的客户要求及其后续拒绝；
- 转折后的真实正向承诺；
- “不是不能”等双重否定；
- 引用问题后再明确“可以答应”的正向背书。

回归覆盖了否定、未覆盖、客户要求、缺失信息、直接背书、转折背书、双重否定和引述后同意八类语境。
