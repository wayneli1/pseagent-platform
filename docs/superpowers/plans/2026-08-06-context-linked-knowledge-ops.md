# PSEAgent 上下文关联知识运营实施计划

日期：2026-08-06  
对应设计：`docs/superpowers/specs/2026-08-06-context-linked-knowledge-ops-design.md`

## 执行纪律

1. 每阶段先验证、后提交；提交标题和正文使用中文并包含“完成内容”“验证结果”。
2. 不暂存用户现有 `docs/local-runbook.md` 和 `.sisyphus/`。
3. 新增上下文关联字段按用户决定暂不加密；现有反馈、完整回答、聊天名和修订草稿继续加密。
4. Knowledge Ops 故障不阻塞已生成回答；上下文持久化失败不得伪造成功。
5. 在线回答与自动复查继续使用现有模型配置，自动复查和修订固定为 `deepseek_v4_flash`。

## 阶段 132：上下文运营边界

- 固化持久会话、父子关系、解析后问题、明文边界和后台信息架构。
- 明确自动复查、聚类和修订 Agent 使用解析后问题，追问不进入答案卡别名。

验证：设计与计划执行 `git diff --check`，无未决策项。

## 阶段 133：会话数据与 API

- 新增会话/轮次 PostgreSQL 迁移、类型、Store、Schema、服务 API 与 RBAC。
- 支持读取活动上下文、幂等追加成功轮次、`/new` 结束会话和旧记录兼容。
- 回答详情返回父问题、原始追问和系统解析问题。

验证：Schema、内存 Store、PostgreSQL、Service、API 与过期/重置/幂等测试。

## 阶段 134：Lunkr 持久上下文

- AnswerService 暴露严格的问题解析元数据。
- Bridge 在回答前恢复 PostgreSQL 上下文，回答成功后保存提纲和父子关系。
- 自动复查和反馈携带同一 request id 的会话关联；持久层故障回退到内存上下文。

验证：问题解析、Bridge、HTTP 客户端、服务重启恢复、用户隔离和 `/new` 测试。

## 阶段 135：复查修订与管理后台

- 自动复查使用解析后的完整问题并接收只读上下文摘要。
- 无答案卡问题按解析后问题聚类；修订 Agent 获取原始追问和父问题信息。
- 自动复查、反馈详情和修订工作台显示父子问题链、系统理解和旧记录降级态。

验证：Worker、Service、后台流程单测、类型检查、构建及 375/768/1024/1440 响应式验收。

## 阶段 136：在线迁移与完整验收

- 迁移现有 PostgreSQL，重启 API、Worker 和 Lunkr Bridge。
- 用第一问、序号追问、新主题和 `/new` 四种场景验证数据库、自动复查和后台展示。
- 执行全仓 TypeScript、Rust、类型检查、生产构建和工作树检查。

验证：服务健康、数据库关系、后台视觉证据、重启后承接和知识库工作树无变化。
