# PSEAgent 逐回答自动复查与低负担反馈实施计划

日期：2026-08-05
对应设计：`docs/superpowers/specs/2026-08-05-live-answer-review-feedback-ux-design.md`

## 执行纪律

1. 每阶段先验证、后提交，commit 标题和正文使用中文，正文包含“完成内容”和“验证结果”。
2. 不暂存现有 `docs/local-runbook.md` 修改和 `.sisyphus/`。
3. 聊天名、问题、回答和知识正文不进入日志、审计元数据或数据库明文列。
4. 自动复查不阻塞已生成回答，复查失败不得伪装成通过。
5. 固定使用 `deepseek_v4_flash`，不改变在线回答各角色模型。

## 阶段90：设计与隐私边界

交付：

- 固化自动复查与用户反馈两条独立链路；
- 固化低负担 `/q` 文案、聊天名加密边界、后台信息架构；
- 固化复查状态、缺陷分类、在线门禁和验收条件。

验证：设计与计划 `git diff --check`，确认无占位符。

## 阶段91：低负担反馈与可识别用户

交付：

- `/q 4` 改为 `review_requested`，原因可选并提供可照抄示例；
- 论客消息标准化提取聊天名；
- 反馈载荷加密保存聊天名，后台显示聊天名；
- 后台支持运营人员纠正反馈分类并记录审计；
- 旧 `correction` 工单保持兼容读取。

验证：治理契约、消息解析、Bridge、Knowledge Ops、PostgreSQL 和管理后台测试、类型检查、构建。

## 阶段92：自动复查数据闭环

交付：

- AnswerReviewCase Schema、加密存储、PostgreSQL migration 和幂等入口；
- 自动复查列表、详情、人工状态和 Dashboard 汇总；
- Bridge 在回答交付后自动提交复查，不依赖 `/q`；
- 引用、答案卡激活摘要和聊天名随加密载荷提交；
- 提交失败不影响回答，但产生脱敏可观测事件。

验证：Store、API、Bridge 幂等与故障隔离测试，数据库明文检查，后台构建和类型检查。

## 阶段93：独立 deepseek 复查 Worker

交付：

- Worker 领取 `answer_review` 作业并更新处理状态；
- 重新编译答案卡、校验引用 revision/hash 并安全读取正式页面；
- `deepseek_v4_flash` 独立严格 JSON 复查器；
- 逐 obligation 覆盖、缺陷分类、严重度、分数和结论；
- 模型、证据或输出异常进入 `errored/open`，不静默通过。

验证：复查器单测、Worker 集成测试、模型名门禁、路径穿越和引用漂移反例。

## 阶段94：答案卡启动门禁与端到端验收

交付：

- 编译当前双知识库答案卡目录；
- 配置期望启用时的目录缺失、空目录和 revision 漂移启动失败；
- 精确答案卡必答项覆盖回归；
- 本地论客回答、自动复查、用户反馈、后台纠类和人工处理全流程验证。

验证：全量 TypeScript 测试与构建、答案卡目录编译、数据库迁移、Knowledge Ops/Worker/Bridge 本地端到端检查和第一题缺项反例。
