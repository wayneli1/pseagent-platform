# PSEAgent 异常驱动知识运营台实施计划

日期：2026-08-05  
对应设计：`docs/superpowers/specs/2026-08-05-exception-driven-knowledge-ops-design.md`

## 执行纪律

1. 每阶段先验证、后提交，提交标题和正文使用中文并包含“完成内容”“验证结果”。
2. 不暂存用户现有 `docs/local-runbook.md` 和 `.sisyphus/`。
3. 数据库/API 枚举保持英文；中文化只属于展示契约。
4. 问题、回答、聊天名和知识正文不进入问题组明文列、日志或审计元数据。
5. 非通过结论只创建人工待办和修订草稿；只有管理员确认且自动验证通过后才能写回和发布。
6. 修订草稿、验证详情中的问题和答案继续加密，作业载荷只传递记录 ID。
7. 单管理员可以完成修订和发布，但系统不得允许跳过验证直接关闭问题。

## 阶段 101：设计与运营边界

- 固化中文状态词典、行动导向总览、问题聚类、优先级、职责和隐私边界。
- 固化问题组生命周期、信息架构和规模化验收条件。

验证：设计与计划执行 `git diff --check`，无占位符。

## 阶段 102：中文状态与行动总览

- 建立穷尽中文状态词典，替换总览、反馈、复查、答案卡、作业、回归、发布和审计页面的裸英文状态。
- 总览展示严重错误、需人工复核、判断冲突、复查异常、自动通过和今日待办。
- 默认隐藏正常记录，提供中文筛选、状态说明和明确下一步动作。

验证：管理台单测、类型检查、构建及中文枚举静态检查。

## 阶段 103：问题中心数据闭环

- 新增 PostgreSQL 问题组与发生记录迁移、类型、Store、API、RBAC 和审计。
- Worker 将 `fail`、`needs_review` 和 `errored` 自动聚类；负面反馈形成或合并问题组。
- 同一来源幂等，统计发生次数、受影响人数、首次和最近发生时间。

验证：内存 Store、PostgreSQL、Service、Worker 聚类与隐私测试。

## 阶段 104：问题中心管理界面

- 新增待办中心和问题中心页面；按优先级和状态筛选，由当前后台管理员统一处理，不设置负责人或分派步骤。
- 问题详情关联反馈和复查元数据，支持分配、状态流转和审计。
- 总览改用服务端问题摘要，正常通过记录只进入统计。

验证：后台类型检查、构建、交互测试和 50+ 条记录分页/渲染检查。

## 阶段 105：全量质量与在线验收

- 执行 PostgreSQL 迁移并重启 API、Worker 和后台。
- 验证现有反馈/复查回填问题组，浏览器检查中文状态和行动队列。
- 执行全仓 TypeScript 测试、类型检查、构建、Rust 测试和工作树检查。

验证：在线健康、数据库计数、浏览器视觉证据和全量命令结果。

## 阶段 110：修订闭环设计

- 固化三层存储、根因路由、Agent 草稿、隔离验证、单管理员门禁和原子发布边界。
- 将问题状态改为由真实修订动作驱动，移除人工任意推进到已解决的能力。
- 固化修订工作台的信息架构、唯一主要操作、失败恢复和隐私要求。

验证：设计与计划执行 `git diff --check`，无占位符或未决策项。

## 阶段 111：修订数据与 API

- 新增修订草稿、验证运行和发布记录 PostgreSQL 迁移、类型、Store 与审计。
- 新增生成、保存、验证、发布、回滚 API；正文加密，列表只返回元数据。
- 由草稿和作业结果自动驱动问题状态；管理员仅可无需处理或重新打开。

验证：Schema、内存 Store、PostgreSQL、Service、API、权限、加密与状态机测试。

## 阶段 112：修订生成和根因路由

- 新增 `deepseek_v4_flash` 修订生成器，严格输出结构化草稿并进行确定性证据校验。
- Worker 按问题关联记录加载原问、原答、复查缺陷和正式证据，生成客户中立答案卡或知识补充建议。
- 无证据、逻辑问题和判断冲突不能伪装为可发布答案卡。

验证：模型契约、证据边界、客户信息去标识、五类用例和失败恢复测试。

## 阶段 113：隔离验证与安全写回

- 在 allowlist worktree 中渲染候选 Markdown，编译候选目录并运行五类定向回归和独立复查。
- 验证通过后允许单管理员发布，写回目标 Obsidian 仓库并生成可审计提交。
- 重新编译答案卡目录和知识索引，创建不可变快照并支持回滚。

验证：路径逃逸、基线漂移、Schema、定向回归、全量门禁、发布和回滚测试。

## 阶段 114：单管理员修订工作台

- 问题详情改为可深链完整页面，提供四步进度、证据区、结构化草稿编辑区和差异预览。
- 去掉问题状态下拉和常规 JSON/Git 输入，只保留当前唯一主要操作与无需处理。
- 增加自动保存、异步进度、失败原因、恢复按钮、键盘焦点和响应式布局。

验证：管理台单测、类型检查、构建、375/768/1024/1440 响应式和浏览器交互验收。

## 阶段 115：在线生效与端到端验收

- 执行 PostgreSQL 迁移，重启 API/Worker，问答服务接入活动目录热加载。
- 使用真实未通过问题完成生成、编辑、验证、发布、再次提问和自动复查全流程。
- 确认发布成功自动关闭、验证失败自动退回、活动版本可回滚且无正文泄露。

验证：服务健康、数据库记录、Git 提交、目录哈希、答案卡激活、正式回答复查、浏览器视觉证据和工作树检查。

## 阶段 116：管理后台账号密码登录

- 管理后台改为账号密码登录，不再要求管理员输入或接触 API Bearer Token。
- 服务端使用 scrypt 密码哈希验证管理员，签发有有效期、可退出吊销、服务重启即失效的内存会话。
- 浏览器仅在当前标签保存管理会话令牌，不保存账号密码；提供密码显隐、自动填充、提交中和内联错误状态。
- 论客 Bridge、Worker 和自动化探针继续使用独立服务 Bearer Token，避免把人工登录凭据扩散到服务链路。
- 管理员账号和密码哈希由未纳入 Git 的环境配置注入，仓库、日志、数据库和审计均不得保存密码明文。

验证：密码哈希、会话签发/过期/吊销、登录 API、服务 Token 兼容、管理台单测与构建、375/1280 浏览器交互、服务重启和全仓回归。

## 阶段 117：完整修订草稿与工作台降噪

- Worker 在生成草稿时用原问题重新匹配当前活动答案卡目录，补足历史问题缺失或过期的答案卡关联，并从当前 Git 修订加载答案卡及必答项正式证据。
- 不可发布的空草稿改为明确阻塞态；知识或目录更新后允许管理员在同一草稿上重新生成，生成中保持幂等。
- 正常草稿必须由 Agent 填充标准答案、同义与口语问法、必答项和五类回归问题；管理台不再把空字段当成可编辑结果。
- 回答变化预览只在新旧答案均存在时显示，移除“等待补充”和修订主页面的高级技术详情；技术标识继续保留在审计与发布数据中。

验证：修订 Agent/Worker 当前目录重匹配测试、服务重生成幂等测试、管理台流程测试、类型检查、构建、在线问题重新生成与浏览器视觉验收。

## 阶段 118：批次发布与并发边界设计

- 固化验证通过后进入待发布池、单库合并提交、双库逻辑批次和 GitHub fast-forward push 顺序。
- 固化复查、生成、验证的受控并发以及同库 Git 写入串行资源锁。
- 移除后台时限心智模型，明确用户反馈继续作为聚类、冲突和修订证据来源。

验证：设计与计划执行 `git diff --check`，批次失败补偿、隐私和双库非原子边界无未决策项。

## 阶段 119：批次数据与 API

- 新增批次及批次项目 PostgreSQL 迁移、类型、Store、Schema、RBAC、Service 和审计。
- 已验证草稿进入待发布池；管理员选择多个草稿创建批次，拒绝重复目标路径和过期验证。
- 单草稿发布入口兼容转换为单项目批次，不再绕过批次门禁。

验证：Schema、内存 Store、PostgreSQL、Service、API、权限、冲突和隐私测试。

## 阶段 120：组合回归、批量写入与 GitHub 同步

- Worker 在联合隔离工作树中编译整个批次并运行组合回归，同库文件合并为单个 Git 提交。
- 安全 Git 组件只允许 fast-forward push 到已配置 upstream，返回可审计同步结果且禁止 force push。
- 双库全部同步后才创建并切换快照；部分 push 失败时生成补偿回滚提交并保持问题未解决。

验证：本地 bare remote 集成测试、同库单提交、双库批次、基线漂移、路径冲突、push 失败补偿、发布与回滚测试。

## 阶段 121：受控并发 Worker

- `claimJob` 支持按作业类型领取，PostgreSQL 继续使用 `FOR UPDATE SKIP LOCKED`。
- 启动复查、草稿生成、验证和维护四类执行池，默认并发分别为 4、3、2、1，支持环境变量覆盖。
- 批次发布按知识库获取跨 Worker 资源锁，避免同库并行写入。

验证：并发领取、类型隔离、执行槽释放、同库互斥和配置边界测试。

## 阶段 122：待发布批次管理界面

- 新增“待发布”页面，展示已验证草稿、目标知识库、冲突检查、批次进度和 GitHub 同步状态。
- 修订工作台验证通过后的唯一主要动作改为前往待发布池，不再单独立即发布。
- 总览与问题列表移除已超时、处理时限和剩余小时，改为人工确认、处理中、待发布和同步失败指标。
- 原始反馈页保留为记录查询，并解释反馈如何形成问题和修订证据。

验证：管理台单测、类型检查、构建、键盘与异步状态、375/768/1024/1440 响应式和浏览器视觉验收。

## 阶段 123：在线批次闭环验收

- 执行 PostgreSQL 迁移并重启 API 与多执行池 Worker。
- 使用至少两个不同问题验证并行生成/验证、待发布选择和单逻辑批次状态。
- 使用本地受控 remote 验证 push；未经用户再次明确点击，不把验收数据推送到真实 GitHub。

验证：服务健康、数据库批次记录、作业并发、Git 提交与远端引用、快照切换、问题关闭、浏览器证据、全仓测试/类型检查/构建和工作树检查。

验收结果：`008_repair_batches.sql` 已应用到现有 PostgreSQL，API 健康且多执行池 Worker 已领取维护任务；受控 bare remote 已覆盖同库单提交、远端同步、跨库失败补偿和整批回滚。全仓 TypeScript 1,555 项与 Rust 38 项测试通过，类型检查和生产构建通过。管理后台已在 375、768、1024、1440 四个宽度完成浏览器验收，无横向溢出；真实知识库未在验收中产生或推送新提交。

## 阶段 124：历史证据与反馈信号设计

- 固化历史引用按当前文件内容哈希重校验、变更引用继续阻断的边界。
- 固化用户反馈分类作为 Agent 的问题信号而非正式证据。
- 固化后台展示证据状态和“重新校验正式证据并生成”的恢复心智模型。

验证：设计与实施计划执行 `git diff --check`，证据完整性、反馈可信边界和发布门禁无未决策项。

## 阶段 125：证据重校验与 Agent 输入

- Worker 接受内容未变化的历史正式引用，拒绝已变化、缺失和不可读引用，并记录重校验数量。
- 修订记录显式携带用户反馈分类；Agent 提示禁止将反馈分类或用户补充当作事实证据。
- 草稿加密载荷和详情 API 返回证据摘要，旧草稿兼容缺省摘要。

验证：证据加载、反馈输入、加密载荷、服务视图和 Worker 单元测试，随后执行全仓测试、类型检查与构建。

## 阶段 126：可解释的证据恢复界面

- 修订工作台展示正式证据数量、历史引用重校验数量和中文不可用原因。
- 阻塞状态主动作改为“重新校验正式证据并生成”，去掉会导致盲目重复执行的文案。
- 保持单一主操作、键盘焦点、中文业务语言和移动端无横向溢出。

验证：管理台流程单测、类型检查、构建和 375/1280 浏览器视觉验收。

## 阶段 127：在线失败草稿恢复验收

- 重启 API 与 Worker，并重新处理当前因历史 revision 被静默丢弃证据的草稿。
- 确认证据摘要由 0 条变为已加载正式证据，Agent 实际执行且结果在后台可见。
- 不提交、发布或推送知识库内容；真实知识库工作树和远端保持不变。

验证：服务健康、作业与草稿数据库状态、浏览器交互、全仓测试/类型检查/构建和四个 Git 工作树检查。

验收结果：API 与多执行池 Worker 已加载新代码，现有问题 `d70be310-cbb8-434f-84e0-112b3ba66062` 的最新草稿 `30003c2c-330a-443b-813b-156509354867` 已生成可发布候选。Worker 对 5 条历史引用完成正文重校验并加载 5 条正式资料，证据问题为 0；`deepseek_v4_flash` 生成 514 字标准答案、6 条同义或口语问法和 5 类回归问题。在线验收同时修复 Windows CRLF 与 Git LF 的等价哈希校验，以及模型常见外层包装、分组必答项和必答项编号格式归一化；归一化后仍执行原严格 Schema、证据路径和发布门禁。管理后台在 1280 与 375 宽度无横向溢出，均显示证据摘要。未提交、验证、发布或推送任何知识库内容，两套知识库 HEAD 与工作树保持不变。
