# PSEAgent 异常驱动知识运营台实施计划

日期：2026-08-05  
对应设计：`docs/superpowers/specs/2026-08-05-exception-driven-knowledge-ops-design.md`

## 执行纪律

1. 每阶段先验证、后提交，提交标题和正文使用中文并包含“完成内容”“验证结果”。
2. 不暂存用户现有 `docs/local-runbook.md` 和 `.sisyphus/`。
3. 数据库/API 枚举保持英文；中文化只属于展示契约。
4. 问题、回答、聊天名和知识正文不进入问题组明文列、日志或审计元数据。
5. 非通过结论只创建人工待办，不自动修改、发布或写回答案。

## 阶段 101：设计与运营边界

- 固化中文状态词典、行动导向总览、问题聚类、优先级、职责和隐私边界。
- 固化问题组生命周期、信息架构和规模化验收条件。

验证：设计与计划执行 `git diff --check`，无占位符。

## 阶段 102：中文状态与行动总览

- 建立穷尽中文状态词典，替换总览、反馈、复查、答案卡、作业、回归、发布和审计页面的裸英文状态。
- 总览展示严重错误、需人工复核、判断冲突、复查异常、自动通过和今日待办。
- 默认隐藏正常记录，提供中文筛选、状态说明和明确下一步动作。

验证：管理台单测、类型检查、构建及中文枚举静态检查。

## 阶段 103：问题中心数据闭环

- 新增 PostgreSQL 问题组与发生记录迁移、类型、Store、API、RBAC 和审计。
- Worker 将 `fail`、`needs_review` 和 `errored` 自动聚类；负面反馈形成或合并问题组。
- 同一来源幂等，统计发生次数、受影响人数、首次和最近发生时间。

验证：内存 Store、PostgreSQL、Service、Worker 聚类与隐私测试。

## 阶段 104：问题中心管理界面

- 新增待办中心和问题中心页面；按优先级和状态筛选，由当前后台管理员统一处理，不设置负责人或分派步骤。
- 问题详情关联反馈和复查元数据，支持分配、状态流转和审计。
- 总览改用服务端问题摘要，正常通过记录只进入统计。

验证：后台类型检查、构建、交互测试和 50+ 条记录分页/渲染检查。

## 阶段 105：全量质量与在线验收

- 执行 PostgreSQL 迁移并重启 API、Worker 和后台。
- 验证现有反馈/复查回填问题组，浏览器检查中文状态和行动队列。
- 执行全仓 TypeScript 测试、类型检查、构建、Rust 测试和工作树检查。

验证：在线健康、数据库计数、浏览器视觉证据和全量命令结果。
