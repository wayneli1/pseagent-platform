# Knowledge Engine 零停机发布实施计划

1. 将 Knowledge Engine 的活动服务改为读写锁保护的不可变服务指针，并增加受鉴权的双知识库热加载接口。
2. 新索引在阻塞线程中完整构建，成功后一次替换；失败时保留旧服务并记录部署状态。
3. 将 4×5 真实回归脚本封装为 Worker 执行器，候选答案卡在写 Git 前运行，报告写入 `regression_runs`。
4. 扩展 `repair_batches`，持久化部署阶段、旧版本服务标志、目标 revision 和质量运行 ID。
5. 发布顺序改为：候选回归、Git 写入、GitHub 推送、引擎热加载、答案卡快照切换、线上对齐核验。
6. 启动 Worker 时执行运行时对账，使已发布快照与长期运行的 Knowledge Engine 自动恢复一致。
7. 管理台增加全局运行状态条、批次阶段时间线和 4×5 回归分组结果。
8. 补充热加载失败保留旧版本、门禁失败禁止 Git 写入、状态文案与迁移测试。
