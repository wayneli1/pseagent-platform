# PSEAgent 第二轮全局准确率端到端验收实施计划

日期：2026-08-07  
对应设计：`docs/superpowers/specs/2026-08-07-second-round-global-accuracy-e2e-design.md`

## 执行纪律

1. 每阶段先验证、后提交；提交标题和正文使用中文，正文包含“完成内容”和“验证结果”。
2. 不暂存用户现有 `docs/local-runbook.md`、`.sisyphus/` 和临时自动化脚本。
3. 20 道新题逐题执行；每题完成通过、资料待补或可审计系统修复后才开始下一题。
4. 不直接调用模型或 AnswerService；真实问答只通过 MCP `pse_answer`。
5. 每个可发布知识修订使用只含一份草稿的发布批次；不得将多道题的修订合并发布。
6. 不为一次失败机械新增硬规则或别名。先按单题知识缺口、正式资料缺口、可复现系统缺陷分类。
7. 应用代码只提交到本地仓库，不推送；知识修订按用户授权通过 Knowledge Ops 正式发布链路同步。

## 阶段 138：设计与第二轮判定门

- 固化全局准确率目标、20 道新题去重边界和逐题闭环。
- 固化三类根因判定、系统缺陷最小复现要求、单题批次发布与五变体复测。
- 固化无资料进入“资料待补”、验收误报检查和最终度量。

验证：设计与计划执行 `git diff --check`，确认无占位符、未决策项或批量发布路径。

## 阶段 139：可复用执行器与新题矩阵

- 让企业验收执行器从显式矩阵路径读取 20 道新题，并支持严格单题选择；保留唯一 MCP 工具及模型身份校验。
- 基于当前正式知识库编制第二轮矩阵，逐题记录证据、事实组、禁答边界和会话预期。
- 自动拒绝与第一轮全部 28 个问法重复、问题 ID 重复、缺少预期或一次选择多题。

验证：执行器单元测试、矩阵 Schema/去重校验、`pse_answer` 工具 Schema 预检、类型检查和 `git diff --check`。

## 阶段 140：20 道新题逐题基线

- 每次只运行一个测试 ID，保存真实 MCP 结果、请求 ID、答案卡命中、证据、确定性检查和自动复查关联。
- 等待每题独立复查完成并核对是否产生问题组。
- 失败先用邻近探针确认是否为系统性缺陷，再分类为系统修复、单题知识修订或资料待补。

验证：每题有开始前预期、真实 MCP 记录、最终复查和根因结论；执行顺序与时间证明没有并行或组批问答。

## 阶段 141：系统修复与单题发布

- 系统性缺陷修改通用实现并增加类别级测试，重启受影响服务后重测原题与邻近探针。
- 有正式证据的单题缺口在修订工作台生成、检查和验证草稿，并用单草稿批次发布。
- 无正式证据的题生成结构化资料清单并进入“资料待补”。
- 每个成功发布的单题完成标准、同义、口语、追问、负例五变体线上复测和独立复查后再继续下一题。

验证：相关定向测试、五类隔离验证、4×5 发布门禁、GitHub 同步、引擎热加载、线上五变体和后台状态全部通过。

## 阶段 142：全量验证与第二轮报告

- 对账 20 题结果、全部发布、资料待补、问题中心、运行中作业、活动 release 和双知识库 revision。
- 运行全仓 TypeScript 测试、Rust 测试、类型检查、生产构建和工作树检查。
- 形成第二轮报告，区分初次失败、验收误报、知识缺口、资料缺口和系统缺陷，并说明对未来问题的全局收益。

验证：报告中的请求、复查、草稿、批次、release、Git revision 和测试结果均可追溯；可操作问题和运行中作业与报告一致。
