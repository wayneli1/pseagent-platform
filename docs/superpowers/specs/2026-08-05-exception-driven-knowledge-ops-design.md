# PSEAgent 异常驱动知识运营台设计

日期：2026-08-05  
状态：已确认，开始实施  
对应基线：`2026-08-05-live-answer-review-feedback-ux-design.md`

## 1. 问题与原则

现有管理台直接展示数据库英文枚举，并把自动复查和用户反馈作为两份原始记录列表。少量数据时尚可追踪；当数百名用户并发提问时，运营人员无法逐条阅读，也无法从 `new`、`triaged`、`needs_review` 等技术状态直接判断今天应处理什么。

本阶段把后台从“记录浏览器”改为“异常驱动工作台”：正常回答由系统自动归档，人工只处理异常问题组。数据库和 API 枚举继续使用稳定英文值，界面、筛选、帮助与操作全部使用中文业务语言。

## 2. 中文状态展示

前端使用一个穷尽类型的状态词典统一展示，不把中文写回数据库。主要映射为：

- 反馈类型：`useful` 回答有帮助、`incorrect` 答案错误、`missing` 信息不完整、`review_requested` 请求人工复查、`evidence` 证据或引用有问题、`correction` 用户提供了纠正；
- 反馈状态：`new` 待处理、`triaged` 已分类、`in_review` 处理中、`resolved` 已解决、`rejected` 已关闭；
- 复查执行：`queued` 等待复查、`running` 正在复查、`completed` 复查完成、`errored` 复查异常；
- 复查结论：`pending` 等待结论、`pass` 复查通过、`needs_review` 需要人工复核、`fail` 复查未通过；
- 人工状态：`open` 待处理、`in_review` 处理中、`resolved` 已解决、`dismissed` 无需处理。

颜色只作辅助；每个徽标必须同时包含可读中文。原始英文值只在技术详情、审计和导出中保留。

## 3. 管理人员职责

系统负责逐回答复查、正常记录自动收敛、异常聚类、优先级、重复合并和技术异常重试。知识运营人员负责异常分流、根因判断、负责人和 SLA；领域专家负责事实与答案卡修订；发布管理员负责回归、发布和回滚。任何模型结论都不能直接改写或发布企业知识。

管理人员的默认入口只回答三个问题：

1. 今天有多少必须处理的事项；
2. 哪类问题影响用户最多或风险最高；
3. 下一步由谁在何时前完成什么动作。

## 4. 行动导向总览

总览顶部展示：严重错误、需要人工复核、用户与模型判断冲突、复查执行异常、即将超时、今日自动通过和自动处理率。原始状态分布下沉为辅助分析，不再作为首屏主信息。

主表为“优先处理的问题组”，按优先级、最后出现时间和影响用户数排序。默认隐藏已通过、已解决和无需处理记录。列表必须支持文本筛选、中文状态筛选、负责人筛选、服务端分页和批量分配；超过 50 行的前端列表使用虚拟化或分页，不一次渲染全部记录。

## 5. 统一问题中心

新增持久化问题组 `issue_cases` 和问题发生记录 `issue_occurrences`。问题组不保存用户原问、原答或聊天名明文，只保存安全标题、卡片标识、缺陷分类、优先级、状态、负责人、SLA 和时间；原始正文仍只存在反馈或复查加密载荷中。

聚类指纹优先使用：知识域 + 答案卡 ID + 缺陷分类；没有答案卡时使用知识域 + 规范化问题哈希 + 缺陷分类。发生记录关联 request id、来源类型、来源记录 id 和伪匿名用户 id，用于计算次数与受影响人数。

问题优先级：

- `P0`：复查 `fail`、关键逻辑冲突或禁答主张；
- `P1`：`needs_review`、用户选择答案错误、用户与模型结论冲突；
- `P2`：信息不完整、请求人工复查、证据问题、重复出现的低风险缺陷；
- `P3`：持续复查异常和一般表达问题。

同一 request id 的反馈和自动复查进入同一问题组；同类记录只增加发生次数，不制造重复工单。`pass` 且无负面反馈不创建问题组；`useful` 只进入统计。

## 6. 问题生命周期

问题组业务状态为：`open` 待确认、`assigned` 已分配、`in_progress` 修订中、`validating` 待验证、`resolved` 已解决、`dismissed` 无需处理。状态变化记录审计事件。

`fail` 和冲突项自动进入待办，但不会撤回已发送回答、修改答案卡或写回知识库。运营人员在详情中查看关联反馈、复查缺陷和受影响数量，分配负责人并推进修订。知识修订、双人审核、Git 写回、回归和在线发布继续是独立受控链路。

## 7. 信息架构

主导航调整为：总览、待办中心、问题中心、答案卡、回归测试、发布中心、审计记录。原始“自动复查”和“用户反馈”作为问题详情中的证据及审计页面保留，不承担主要分流职责。

桌面端采用高密度、低装饰、Slate 中性色和蓝色主操作。严重、警告、处理中、成功和中性状态使用语义色并配文字；焦点可见，主要操作点击区域不低于 44px，异步操作提供进行中与错误恢复提示。

## 8. 验收

- 管理台业务页面不出现裸英文枚举；数据库仍保留原英文值；
- 总览首屏展示必须处理的异常和明确中文动作，而非原始状态堆叠；
- `pass` 正常记录默认不进入人工待办；
- `needs_review`、`fail`、负面反馈和执行异常自动形成或合并问题组；
- 相同问题组正确累计发生次数与受影响用户数；
- 问题组不新增问题、回答、聊天名或知识正文的明文列；
- 管理人员可按中文优先级、状态和负责人筛选，并流转问题状态；
- 所有流转写入审计；
- PostgreSQL 迁移、服务、Worker、后台测试、类型检查、构建和浏览器验收通过。
