# 可靠性负载门禁设计

日期：2026-08-11

## 目标

把现有只输出统计的 `probe:reliability-load` 变成可自动阻断发布的门禁，同时保持并发 1、2、4、10 四档的诊断明细。

## 采用方案

每个并发档独立应用同一组企业阈值：

- 成功率不低于 99.5%；
- P95 不高于 120,000 ms；
- P99 不高于 180,000 ms。

门禁必须同时收到且只收到并发 1、2、4、10 四档结果。缺少并发档、重复并发档或任一档任一指标失败，整体 `qualified` 均为 `false`。当前每档 10 题，因此成功率阈值实际要求 10/10。

不采用把四档合并成一个总体成功率的方式，因为总体平均会掩盖单用户或高并发档的独立退化；也不再依靠人工读取 stdout 判定。

## 数据流

`summarizeReliabilityLoad` 继续产生每档原始统计。新增纯函数 `evaluateReliabilityLoadGate` 接收四档统计，输出：

- 固定阈值；
- 缺失并发档；
- 每档成功率、P95、P99 三个硬门；
- 整体 `qualified`。

探针把门禁对象写入现有临时 JSON 报告，在摘要中输出 `qualified`，失败时设置非零退出码。原始逐题记录和诊断字段不改变。

## 测试

- 四档全部满足阈值时通过；
- 任一档成功率不足时失败；
- 任一档 P95 或 P99 超限时失败；
- 缺档时失败；
- 重复并发档或非 1/2/4/10 的额外并发档时拒绝无歧义输入。

## 边界

本变更只修改 `pseagent-platform`。不修改题集、知识仓库、模型配置或企业阈值；不把负载题结果当作事实准确率。
