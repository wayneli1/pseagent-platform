# 项目数据证据边界与稳定修订验证设计

日期：2026-08-06
状态：已确认，开始实施

## 1. 问题

修订草稿可能同时要求回答正式证据中的项目规模数据，又在 `forbiddenClaims` 中笼统禁止“某项目具体用户数”。当前验证将这类规则继续交给模型判断，造成同一草稿在“应补充数字”和“不得出现数字”之间摇摆，后台只显示笼统失败，管理员无法定位应修改答案、规则还是证据。

## 2. 统一规则

正式证据直接记载的项目用户数、授权量、服务器数、节点数和部署规模可以回答，但必须同时满足：

- 数值与项目、场景、时间和口径绑定；
- 不跨项目套用，不扩大为通用产品容量或新客户承诺；
- 历史数据不描述为当前实时数据；
- `约、等于、超过、不少于` 等比较口径不得互换；
- 没有正式证据直接支持的数据不得发布。

答案卡不得生成“禁止出现某项目具体用户数/授权量/服务器数量/节点数量/所有项目规模数据”等宽泛规则。此类规则应改写为防止跨项目套用、实时化、容量上限化和承诺化的边界。

## 3. 验证架构

修订验证按以下顺序执行：

1. 编译候选答案卡和正式证据包；
2. 运行确定性规则预检，检查必答项、禁答项、答案正文、证据和数值口径的冲突；
3. 发现规则冲突时立即返回 `rule_conflict`，不调用修订 Agent 或独立复核模型；
4. 无规则冲突时执行五类问法验证和独立内容复核；
5. 对证据支持、项目归属、跨项目套用、当前承诺和数值比较符执行确定性事实检查；
6. 对草稿、证据和候选目录计算指纹；未发生变化的重复验证复用上次结果，不再次依赖模型抽样。

## 4. 诊断契约

每个失败项至少包含：验证阶段、必答项 ID、字段、触发原文、冲突规则、证据路径和建议动作。规则冲突单独展示，不得归并为普通“答案未通过”。管理员可从诊断直接定位右侧答案或对应必答项字段。

## 5. 存量审计

提供只读审计命令扫描两个知识库的 `requiredConcepts`、`forbiddenClaims`、`preferredEvidencePaths` 和 `answerTemplate`，输出卡片 ID、必答项、原规则、建议规则、原因和证据路径。迁移只修改确定命中过宽规则且与正式证据冲突的项；安全、保密、无证据推断、跨项目套用和过度承诺规则继续保留。

本次扫描覆盖两个仓库的 33 个 `wiki/queries` 页面，其中 13 张采用 `card_schema_version: 1` 的版本化答案卡进入规则扫描。已发布卡未发现需迁移项；当前 PostgreSQL 草稿 `PRO-REPAIR-00ACF6DA6848` 的 O1 需要将“华为项目具体用户数”改为精确边界。

## 6. 后台交互

验证失败区采用内联“原因 + 位置 + 恢复动作”结构：

- 标明失败阶段和问题类型；
- 显示 O1/O2 等必答项与具体字段；
- 引用触发失败的答案原文和规则；
- 给出“修改答案、修改规则、补充证据、人工复核”之一；
- 支持跳转并聚焦对应编辑字段；
- 未修改草稿重复验证时提示将复用结果，不会自动修复冲突。

## 7. 验收

- 正式证据支持的华为 10 万、2 万和比亚迪约 44 万数据可通过；
- 跨项目套用、实时容量承诺、无证据数字和错误比较口径不能通过；
- 规则自身冲突在模型前稳定拦截；
- 五类验证对未修改草稿返回稳定结果；
- 不因答案模板缺少运行时 `[1]` 引用编号而失败；
- 后台显示阶段、必答项、字段、原文、规则和建议；
- 现有安全边界、编译、类型和测试不回归。
