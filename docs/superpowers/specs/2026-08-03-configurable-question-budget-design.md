# 可配置问题处理时限设计

日期：2026-08-03

## 背景

论客机器人当前把每个问题的完整处理时限固定为 300 秒。复杂知识问答可能在生成最终答案前耗尽这 300 秒，随后桥接层返回“知识问答服务暂时不可用”，长回答也就无法进入 `.txt` 文件发送阶段。

本次只调整时限配置和传递方式，不改变知识检索、回答生成、重试、长文本文件上传及降级分段的业务逻辑。

## 目标

- 允许按部署环境把单题总时限设置为 300 秒以上。
- 保留现有默认值，未配置新变量时行为兼容当前版本。
- 给最终文件上传预留明确的发送窗口。
- 单次模型请求仍限制为 180 秒，避免一次模型调用占满整题时限。
- 对错误配置尽早失败，不让机器人带着相互冲突的时限启动。

## 三层时限

| 层级 | 环境变量 | 默认值 | 本机部署值 | 职责 |
| --- | --- | ---: | ---: | --- |
| 论客整题 | `LUNKR_QUESTION_BUDGET_MS` | 300000 | 600000 | 从消息入队开始，覆盖排队、PSE 回答、重试和最终发送 |
| PSE 请求 | `PSE_REQUEST_TIMEOUT_MS` | 300000 | 570000 | 限制一次 `AnswerService` 请求的总执行时间 |
| Agent 主动收尾 | `PSE_ACTIVE_DEADLINE_MS` | 270000 | 540000 | 传给知识 Agent 的绝对截止时间，促使它在请求超时前完成整理 |
| 单次模型调用 | `PSE_MODEL_TIMEOUT_MS` | 60000 | 180000（保持现状） | 限制任意一次模型 HTTP 调用 |

本机部署形成 `540 秒 < 570 秒 < 600 秒` 的梯度：Agent 有 30 秒完成上层收尾，PSE 返回后桥接层还有 30 秒发送文本或 `.txt` 文件。

## 配置规则

- 三个新时限必须是整数毫秒，范围为 30000 至 1800000（30 秒至 30 分钟）。
- PSE 配置必须满足 `PSE_ACTIVE_DEADLINE_MS < PSE_REQUEST_TIMEOUT_MS`，否则启动失败并给出明确错误。
- `PSE_REQUEST_TIMEOUT_MS < LUNKR_QUESTION_BUDGET_MS` 是论客部署约束。两个模块也可独立运行，因此不在各自配置解析器中做跨模块强耦合校验；示例配置和本机配置保持至少 30 秒发送余量。
- `PSE_MODEL_TIMEOUT_MS` 的上限仍为 180000，不随整题时限自动放大。

## 运行逻辑

1. 论客桥接层收到问题时创建 `LUNKR_QUESTION_BUDGET_MS` 的总预算信号，排队时间仍计入预算。
2. `AnswerService` 再创建 `PSE_REQUEST_TIMEOUT_MS` 的内部信号，并与论客传入信号合并。
3. 知识 Agent 获得 `开始时间 + PSE_ACTIVE_DEADLINE_MS` 的主动截止时间。
4. 回答成功后沿用现有发送规则：不超过 1000 字直接发送，超过 1000 字优先上传为 `.txt`，上传重试失败才降级分段。
5. 任一外层信号先到期时，沿用现有 `temporarily_unavailable/model_unavailable` 结果和用户提示。

## 兼容性与风险

- 默认值不变，现有未设置环境变量的部署不会被隐式延长。
- 延长整题时限会增加单个会话占用执行槽的时间；现有每用户串行队列、全局并发和排队上限保持不变。
- 重启会清空内存中的会话上下文和问题编号，编号重新从 `#1` 开始；不重启独立运行的 Knowledge Engine。
- 600 秒是上限预算，不表示每个问题都会等待 600 秒；正常回答完成后立即发送。

## 验收标准

- 配置测试覆盖默认值、自定义值、非法范围和 PSE 时限顺序冲突。
- AnswerService 测试证明请求超时和 Agent 截止时间使用注入配置，而非固定常量。
- 论客桥接测试证明总预算来自配置，300 秒默认行为仍兼容。
- 本机配置生效为 600000/570000/540000，机器人安全重启后完成连接、认证和 ready。
- 重启后只有一个论客机器人主进程，Knowledge Engine 健康状态不受影响。
