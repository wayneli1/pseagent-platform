# PSEAgent 知识运营管理后台分页设计

日期：2026-08-07  
状态：已确认，开始执行  
对应基线：`2026-08-05-exception-driven-knowledge-ops-design.md`、`2026-08-06-zero-downtime-knowledge-release-design.md`、`2026-08-07-evidence-needs-card-pagination-design.md`

## 1. 目标

为知识运营管理后台的原始记录、待发布、回归评测、发布与回滚、审计日志五个页面补齐分页，避免记录增长后一次读取和渲染全部历史数据。分页必须使用明确的服务端总数和当前页数据；固定的 4×5 回归题目计划可在浏览器内分页，但不得改变服务端执行计划或运行顺序。

本次不改变记录的加密边界、权限模型、发布时间线、回滚语义或回归门禁，只改变列表读取契约和页面导航。

## 2. 页面范围

### 2.1 原始记录

“问答与自动复查记录”和“用户负面反馈”使用两套互不影响的分页状态，每页 25 条。复查结论和反馈状态筛选由服务端执行，筛选变化时回到第一页；页面显示筛选结果总数，不得只过滤当前页后继续显示全量总数。

两类列表仍只返回元数据，原问、原答、复查详情和会话关系继续在打开详情时单条解密读取。

### 2.2 待发布

“待发布池”和“最近发布批次”分别使用服务端分页，每页 25 条。跨页勾选的待发布草稿保存在当前浏览器页面状态中；当刷新后草稿已不再处于 `ready_to_publish` 时，系统从选择集合移除该草稿。

批次自动刷新期间保留当前页。创建批次后清空选择并回到待发布池第一页，最近批次回到第一页，以便立即看到新批次。

### 2.3 回归评测

固定 20 道回归题目按每页 10 条在浏览器内分页，分页只影响展示，不影响四组并行、每组五轮串行的执行顺序和实时进度合计。

回归运行历史使用服务端分页，每页 25 条。活动作业仍用于推导实时状态，但页面不再把无界作业列表作为历史记录一次性渲染。

### 2.4 发布与回滚、审计日志

发布记录和审计事件均使用服务端分页，每页 25 条。回滚按钮只作用于当前页对应的明确版本，翻页不改变活动版本。审计元数据仍按单条事件在抽屉中展开。

总览只读取最近一条发布记录，不为获取“最近发布”加载完整发布历史。

## 3. API 契约

下列列表接口统一接受 `limit` 和 `offset`，其中 `limit` 为 1 到 100，默认 25，`offset` 不得小于 0：

- `GET /v1/answer-reviews`
- `GET /v1/feedback`
- `GET /v1/repair-drafts/ready`
- `GET /v1/repair-batches`
- `GET /v1/regression-runs`
- `GET /v1/releases`
- `GET /v1/audit`

响应统一为：

```json
{
  "items": [],
  "total": 0
}
```

原始记录接口额外接受现有业务筛选：复查记录支持 `verdict` 或 `actionable=true`，反馈支持 `status` 或 `actionable=true`。同一请求不得同时提交具体状态与 `actionable=true`，避免筛选语义冲突。

内存 Store 先按既有顺序排序和筛选，再切片并返回筛选后的总数；PostgreSQL Store 使用同一筛选条件分别执行 `LIMIT/OFFSET` 查询和 `count(*)`，不得先读取全表再分页。所有列表继续使用当前确定性排序，时间相同时追加稳定 ID 排序，避免翻页时重复或漏项。

## 4. 交互与可访问性

每个分页区显示“显示 起始–结束 / 总数”，空列表显示 `0–0 / 0`。上一页和下一页使用原生 `button`，首页和末页分别设置真实 `disabled`；分页控件支持键盘操作并保留现有可见焦点样式。

分页状态彼此独立，切换页面时保留当前会话内状态；筛选变化重置对应列表偏移量。若数据变化导致当前偏移量超出最后一页，页面自动回到新的最后一页，不展示伪空状态。

375px 宽度下分页说明和按钮组改为纵向排列，表格继续使用现有响应式容器，不产生页面级横向滚动。实时刷新只更新内容，不重置当前页，也不以颜色作为唯一状态提示。

## 5. 安全与兼容性

- 继续在 Service 层执行既有 RBAC，不新增匿名列表入口。
- 原始问答和复查正文仍保持加密存储，分页列表只处理未加密元数据。
- 详情、发布、回滚、审计写入和 Worker 状态机接口不变。
- 所有仓内调用方同步迁移到分页响应；不保留同一路径的数组兼容分支，避免客户端误判总数。
- 分页参数校验失败返回现有 `validation_failed`，不得回退为无界列表。

## 6. 验收标准

- 五个目标页面均能通过上一页、下一页浏览记录，并正确显示起止范围与总数。
- 原始记录的两套筛选和分页组合准确，切换筛选回到第一页。
- 待发布两套分页互不干扰，草稿选择可跨页保留，自动刷新不跳页。
- 回归题目分页不改变 20 题总进度，运行历史只加载当前页。
- 发布、审计接口和 PostgreSQL 查询不再无界读取历史记录。
- 首尾页、空列表、恰好一页、最后不足一页和数据收缩后的越界偏移均有自动化测试。
- 管理后台测试、服务测试、类型检查、生产构建和 `git diff --check` 全部通过。
