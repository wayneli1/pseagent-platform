# PSEAgent 确定性可靠性控制平面设计

日期：2026-08-11

状态：待书面审阅

实施分支：`fix/100题可靠性整改-第二阶段`

## 1. 背景与核心判断

第三套全新百题三轮冷运行没有达到企业级门槛。失败并不等于大模型完全不会回答，也不等于知识库整体不可用：单域专业题和通用题的事实/义务准确率均为 95%，主要损失集中在混合域路由、义务完整性、主张—引用绑定、合理拒答、跨轮一致性和模型长尾。

大模型即使设置 `temperature: 0`，仍可能因服务端实现、并发调度、浮点计算、上下文边界和上游模型版本产生不同输出。因此本轮不把“让模型每个字都相同”设为目标，而把稳定性合同定义为：

- 同一冻结输入、代码、政策和知识修订下，路由域集合不得因模型措辞变化而变化；
- 必答原子义务集合不得因模型漏拆而变化；
- 安全处置不得因模型漏判而进入普通检索；
- 没有证据绑定的主张不得发布；
- 最终状态只能由义务完成状态归并，不能从答案文字反推；
- 高风险事实只有在证据、程序校验和共识均通过时才能发布；
- 已通过全部门禁的生产答案可以复用，但冷运行验收必须关闭缓存。

模型仍可以决定检索措辞和低风险表达方式，但不能再决定系统合同。

## 2. 已确认的实现缺口

当前实现已经提供 `TaskSpec`、`DomainKnowledgePlan`、`EvidenceLedger`、确定性覆盖门、统一请求截止时间和四个模型角色，但还存在以下结构性缺口：

1. `ModelTaskCompiler.compile` 最多进行三次开放式模型修复；模型首先决定义务数量，确定性 guard 主要在事后发现显式遗漏，不能保证每个用户请求原子都进入契约。
2. 混合域激活仍包含 `requiresMixedKnowledgeDomains` 的词面窄规则；虽然 `deriveDomainKnowledgePlans` 能按 obligation 的 domains 执行，但前提是模型已经完整拆出并正确标域。
3. `request-policy.ts` 在路由前运行，但主要通过若干 `all: RegExp[]` 精确命中同义表达；未命中时危险请求会落入普通知识链路。
4. `RequestBudget` 只有总预算和临时阶段 signal，没有不可挪用的阶段保留；一次慢 `planner.compile` 可以吞掉后续合成和验证时间。
5. `EvidenceLedger` 的 claim 记录只有序号、状态、引用和方面 ID，没有稳定的主张文本、义务 ID 和证据片段身份，最终仍可能出现“有引用但未在同一语义单元支持主张”。
6. `response.ts` 已按 coverage 归并状态，但 coverage 本身仍受生成与语义验证波动影响；`policyDisposition` 仍会从答案文本反推。
7. 正常回答、任务编译、引用修复、语义修复和覆盖验证允许多次开放式重写；模型尝试数在第三套盲测中达到 P50=5、P95=8、最大 12。
8. 没有生产合格答案缓存，也没有高风险结论共识合同。
9. 盲测评分器对否定范围、用户原话复述、引号、引用语义单元和通用拒答的识别仍有误差。

## 3. 目标与非目标

### 3.1 目标

本设计覆盖十项已批准目标：

1. 原子义务结构化和程序校验；
2. 按义务并集决定双域；
3. 安全策略前置和固定拒答合同；
4. 每阶段独立时间预算与快速降级；
5. 主张—引用程序化绑定；
6. 根据义务完成情况确定最终状态；
7. 减少开放式模型重写次数；
8. 高风险共识与生产合格答案缓存；
9. 修正验收器的否定、引用和拒答识别；
10. 使用第四套全新 100 题完成三次冷运行验收。

最终门槛沿用第三套冻结门槛：300 次链路成功率不低于 99.5%，首次事实/义务准确率不低于 95%，高风险准确率不低于 99%，主张证据支持率不低于 98%，路由准确率不低于 98%，完整率不低于 95%，合理拒答率不低于 95%，同题三次结论一致率不低于 95%，P95 不高于 120 秒，P99 不高于 180 秒，无证据关键主张和错误危险发布均为 0。

### 3.2 非目标

- 不要求三轮自然语言逐字一致；
- 不以同题多跑后选择最好答案；
- 不通过继续堆单题关键词、答案卡或知识材料掩盖平台缺陷；
- 不把第三套百题继续当作独立终验集；
- 不修改 `coremail-professional` 或 `presales-general`，除非后续独立证据审计确认真实资料缺口；
- 不向知识运营、反馈、Jira 或 Wiki 写入验收数据。

## 4. 方案选择

### 方案 A：只增加采样次数或改用多数投票

多数投票会增加延迟和成本，而且同一模型的错误高度相关。它还会掩盖单次危险输出，不能满足“错误发布为 0”。不采用。

### 方案 B：只降低 temperature、固定 seed 或更换模型

这些手段可以降低波动，但不能保证义务完整、双域执行、引用绑定和安全合同。模型服务也未必提供端到端可重复 seed。它们可以作为运行配置优化，不能作为可靠性架构。拒绝作为主方案。

### 方案 C：确定性控制平面包围有限模型调用

采用。程序先冻结安全处置、原子义务、域并集、阶段预算和证据身份；模型只在受限 schema 内做分类、检索措辞和草稿表达；程序再按义务和证据图决定可发布内容、状态、降级与缓存资格。

## 5. 总体数据流

```text
请求
  -> PolicyPreflight（确定性政策族；必要时短时语义分类）
      -> 固定四段拒答，直接结束
  -> ReleaseFingerprint + QualifiedCache lookup
      -> 合格命中，返回已验证答案
  -> QuestionResolution
  -> ObligationAtomizer（从原文跨度产生原子义务种子）
  -> StructuredTaskClassifier（一次 JSON 分类）
  -> ObligationContractGuard（补齐/拒绝/确定性降级）
  -> DomainUnion（按必答义务 domains 并集）
  -> DeterministicRetrievalCoordinator（双域并行检索与 EvidenceLedger）
  -> StructuredClaimDraft（每域至多一次 JSON 草稿）
  -> ClaimEvidenceGraphGate（程序绑定、删除无证据主张）
  -> HighRiskConsensus（仅高风险；一致才发布）
  -> ObligationOutcomeReducer（程序归并状态）
  -> DeterministicRenderer（固定引用与拒答格式）
  -> QualifiedCache write（仅全门禁通过）
  -> AnswerResult
```

每一阶段只消费自己的截止时间。模型超时、无效 JSON 或共识不一致都转为明确的义务状态或固定安全降级，不再触发无界的整答重写。

## 6. 原子义务合同

### 6.1 数据结构

在现有 `TaskSpec` 上增加可审计字段，形成内部 `AtomicObligation`：

```ts
type AtomicObligation = {
  id: `O${number}`;
  sourceSpan: { start: number; end: number };
  sourceText: string;
  kind: "fact" | "comparison" | "diagnosis" | "recommendation" |
    "procedure" | "risk_assessment" | "case_judgement";
  targetEntityIds: readonly string[];
  domains: readonly ("coremail-professional" | "presales-general")[];
  evidencePolicy: "direct" | "synthesis" | "customer_input";
  evidenceTypes: readonly ("formal_page" | "version_matrix" | "customer_fact" |
    "policy" | "method")[];
  risk: "low" | "high" | "prohibited";
  completionCriteria: readonly string[];
  required: true;
};
```

`sourceSpan` 必须精确映射 `standaloneQuestion`；`sourceText` 必须等于该跨度的原文，模型不得改写。`completionCriteria` 描述可程序检查的输出条件，不存放预期答案或测试题专用关键词。

### 6.2 两步编译

第一步由现有 `analyzeObligationSource`、`extractExplicitQuestionSignals` 和会话主题绑定生成 `ObligationSeed[]`。种子数量和原文跨度由程序决定，显式并列请求、比较对象、方法与个案结论必须分别保留。

第二步只允许一次模型 JSON 调用，把每个 seed 分类为 kind、domains、evidencePolicy、evidenceTypes 和 risk；模型不能删除 seed、合并 seed、修改跨度或增加没有原文来源的必答义务。schema 校验失败后不再要求模型“从头重写”，而是用 scope、显式技术实体、产品中性治理信号和证据类型进行确定性分类兜底。

### 6.3 程序 guard

`ObligationContractGuard` 必须验证：

- 每个显式请求跨度至少被一个必答义务覆盖；
- 每个义务只覆盖一个独立可判定目标；
- source spans 不交叉吞并，允许同一比较义务绑定多个比较实体；
- `customer_input` 与知识可回答的方法义务不得互相替代；
- 直接事实、版本、数字、支持性、兼容性、认证和承诺必须使用 direct；
- 所有必答义务均有 domain、risk 和 completion criteria；
- 无法无歧义修复时返回审计化部分回答，不退回旧的宽泛整题规划。

## 7. 按义务并集决定知识域

知识域集合唯一计算方式为：

```ts
domainsUsed = orderedUnique(requiredObligations.flatMap(item => item.domains));
```

主 `scope` 只决定展示主语和兼容外部协议，不得裁掉另一个域。只要必答义务并集包含两个域，就必须创建两个 `DomainKnowledgePlan`，并行打开两个冻结修订、分别检索、分别建立主张—证据绑定，再按原义务顺序合并。

删除运行正确性对 `requiresMixedKnowledgeDomains(question)` 窄词表的依赖；该函数只可保留为诊断提示或兼容回归，不能再决定是否修复 domains。若任一必答义务没有域，guard 必须在执行前失败，不允许模型路由结果替代义务域。

双域门禁同时检查：义务域并集、实际 session 项目、`domainsUsed`、每域引用修订和最终每义务引用归属。只出现两个来源但义务域错误不能算通过。

激活原子义务链路后，检索不再沿用当前最多 40 个回合的“模型选择下一工具动作”循环。`DeterministicRetrievalCoordinator` 直接执行由 obligation 适配出的 seed queries，按义务独立进行候选排序、批量读页和一次程序化查询变体扩展；停止条件由方面覆盖、读页上限、无增益和检索阶段截止时间决定。模型不能通过反复选择 search/read 动作扩大调用次数，也不能提前跳过尚未处理的必答义务。旧 agent loop 只在新控制面开关关闭时保留为兼容路径。

## 8. 安全策略前置与固定拒答合同

### 8.1 前置判定

`PolicyPreflight` 必须在路由、问题解析、缓存和知识检索之前运行。判定分两层：

1. 确定性政策族识别授权绕过、凭据/隐私泄露、审计规避、记录伪造、欺诈承诺、贿赂、非法竞争情报、未经同意的数据处理等稳定意图；
2. 对出现风险动作、受保护对象或不当目的但没有确定命中规则的请求，执行一次短时结构化语义分类，输出 `allowed | prohibited | uncertain` 和政策族。确定性命中不可被模型降级；模型超时、无效或 `uncertain` 一律走安全限制/升级，而不是普通检索。

政策语义分类只输出处置标签，不生成答案。

### 8.2 四段拒答合同

每个政策族保存结构化模板字段，由程序固定渲染：

1. 明确不能执行、协助或承诺的边界；
2. 风险和受保护对象；
3. 合规、安全且可执行的替代方案；
4. 审批、升级、审计或事件处置路径。

返回值直接写入 `policyDisposition`，禁止再从最终中文文本反推。完整履行拒答义务时 `status=answered`；需要补充合法授权或人工裁决时 `policyDisposition=needs_escalation`。固定拒答不调用通用合成模型，也不进入答案缓存。

## 9. 阶段预算和快速降级

默认外部请求预算保持 180 秒，活动预算 165 秒，最后 15 秒只用于确定性收口和返回。引入 `StageBudgetAllocator`，按绝对截止点保留后续预算：

| 阶段 | 最大时间 | 超时后的确定性行为 |
| --- | ---: | --- |
| 政策语义复核、发布指纹与缓存 | 10 秒 | 风险请求安全限制；缓存旁路 |
| 问题解析、原子义务编译与 guard | 25 秒 | 使用原文原子和确定性分类兜底 |
| 会话快照与双域并行检索 | 50 秒 | 保留已读取证据，未完成义务记为 retrieval gap |
| 结构化主张草稿 | 40 秒 | 使用已验证证据的确定性摘录/缺口模板，不整答失败 |
| 程序验证与高风险共识 | 25 秒 | 删除未通过主张；高风险转限制或拒答 |
| 一次定点修订 | 10 秒 | 删除失败义务的未支持主张，禁止再次重写 |
| 最终归并与渲染 | 5 秒 | 固定部分回答、拒答或临时不可用合同 |

阶段提前完成不改变后续硬截止点；阶段不得借用后续保留时间。双域在同一检索阶段并行，共享总并发配额但各有最小保留。所有子调用继续共享请求信号和模型队列，不能把局部 timeout 当成新的 180 秒。

仅当连审计化的缺口或安全响应都无法构造时才返回 `temporarily_unavailable`。模型、验证器或单一域不可用时，优先返回有明确缺口的部分回答。

## 10. 主张—引用程序化绑定

### 10.1 主张图

结构化草稿不直接返回 Markdown，而返回 `ClaimDraft[]`：

```ts
type ClaimDraft = {
  claimId: `CL${number}`;
  obligationId: `O${number}`;
  domain: KnowledgeDomain;
  text: string;
  kind: "fact" | "method" | "boundary" | "gap";
  citationIndexes: readonly number[];
  coveredAspectIds: readonly string[];
};
```

`ClaimEvidenceGraphGate` 对每条主张验证：引用必须来自该域同一冻结修订、引用页面已经成功读取、引用已归属同一 obligation、所声明方面已被证据覆盖、direct 主张不能使用 summary-only 或 historical 来源。失败的主张被删除并记录 gap，不能通过把引用统一放在答案尾部来通过。

`EvidenceClaimRecord` 增加稳定 claimId、规范化主张文本哈希、obligationId、domain、证据页面身份和支持模式。原始证据正文不写入公共诊断，只保留路径哈希、修订和必要片段哈希。

### 10.2 确定性渲染

每个义务渲染为独立列表项或段落；该义务所有事实主张的引用必须放在同一项内。资料来源附录由 references 自动生成，模型不得生成或重排引用编号。混合域先分别完成绑定再按义务原始顺序合并，禁止合并阶段丢掉来源归属。

## 11. 义务完成状态与最终状态

每个必答义务只能进入以下内部状态之一：

- `complete`：完成条件全部满足，所有可验证主张均有有效证据；
- `partial`：安全地完成一部分，明确列出缺口；
- `not_covered`：没有足够正式证据；
- `missing_input`：缺少当次客户事实；
- `policy_blocked`：危险请求已按固定拒答合同完成；
- `unavailable`：依赖阶段不可用且没有可发布主张。

归并规则由程序固定执行：

- 所有必答知识义务 `complete`，且客户输入义务不是 missing 时，`status=answered`；
- 至少一个义务有可发布内容且至少一个义务为 partial/not_covered/missing_input/unavailable，`status=partially_answered`；
- 所有知识义务均为 not_covered 且没有方法或边界义务完成，`status=not_covered`；
- 政策请求的四段拒答义务完整完成时 `status=answered`，处置来自政策层；
- 只有无法构造可信答案、缺口或拒答合同的基础设施失败才是 `temporarily_unavailable`。

内部候选没读完、草稿主张被删除或可选验证器不可用不能自动把已完整义务降级。`knowledgeCoverage`、`caseAssessability`、`policyDisposition` 和外部 `status` 均从结构化状态生成，禁止从答案文字反推。

## 12. 限制开放式模型重写

一次知识请求的默认开放式调用上限改为：

- 问题解析：多轮且无法确定绑定时至多一次；单轮默认不调用；
- 义务分类：一次结构化 JSON；失败走程序兜底；
- 检索动作选择：零次模型调用；seed、排序、读页、补充变体和停止条件均由程序执行；
- 每个实际知识域的主张草稿：至多一次结构化 JSON；
- 普通低风险答案：程序门通过后不再调用语义重写；
- 高风险验证：只输出 verdict JSON，不生成答案；
- 定点修订：整个请求最多一次，只能替换失败 claim，不能重写已经通过的义务；
- 引用编号、来源附录、状态、拒答和 gap 全部由程序渲染。

禁止任务编译三次重写、普通回答两次从头重写、引用修复两次加整体验证重写的乘法组合。每个诊断必须记录 `modelCallBudget`、`modelCallsUsed`、角色、结构化/开放式类型和是否降级。

## 13. 高风险共识

高风险义务包括安全、权限、隐私、法律/合同承诺、合规结论、认证、确定 SLA、性能保证、不可逆操作和对第三方的负面事实。

高风险事实发布需要同时满足：

1. direct 正式证据和程序化主张绑定通过；
2. 两次相互隔离的 verifier verdict 对 `supported | contradicted | insufficient`、主张哈希和引用集合给出一致结论；
3. 禁止主张和政策门均通过；
4. 两次 verdict 都在独立阶段预算内完成。

不做多数投票，也不从多个草稿中挑最好答案。两次 verdict 不一致、任一不可用或任一认为证据不足时，只保留双方一致支持的安全交集；若交集不能完成义务，则返回限制/拒答和升级路径。

如果两个 verifier 角色配置为同一底层模型，诊断必须标记为 `repeated_same_model`，不能宣称独立模型裁判；真正的 `independent_models` 只有在模型标识不同时成立。无论哪种配置，程序证据门始终是发布前提。

## 14. 生产合格答案缓存

### 14.1 缓存键

新增可注入 `QualifiedAnswerCache`，默认关闭；生产启用时使用内容寻址的持久化文件缓存。键的 SHA-256 输入包括：

- 规范化原始问题和会话上下文哈希；
- 代码发布 ID；
- 专业与通用知识修订；
- 政策合同版本；
- 答案卡 catalog hash；
- 缓存 schema 版本。

知识或政策任一变化都会自然失效。缓存文件名只使用哈希，不包含客户原文。写入采用临时文件加同目录原子 rename；并发写同一内容键必须幂等。

### 14.2 写入资格

只有同时满足以下条件才写入：

- `status=answered`；
- 所有必答义务 complete；
- 无 coverage gap、无 missing input、无 unavailable；
- 所有事实 claim 的证据绑定通过；
- 无历史线索替代正式证据；
- 高风险义务已通过共识；
- 代码发布 ID、知识修订和 catalog hash 均可确定；
- AnswerResult 和内部缓存 schema 重新解析通过。

不缓存部分回答、知识缺口、临时不可用和政策拒答。缓存记录保存已验证的 AnswerResult、域集合、义务结论签名、引用修订和资格证明；每次命中重新验证 schema、键和引用修订，并生成新的 requestId 和 cache-hit 诊断。

### 14.3 验收隔离

第四套百题三次终验必须设置 `PSE_QUALIFIED_CACHE_ENABLED=false`，报告标记 `cacheMode=cold_disabled`。缓存只能在独立的暖运行测试中验证命中率、延迟和内容一致性，暖缓存结果不得计入事实准确率、首次泛化或三轮一致率。

## 15. 验收器校准

评分器升级为新版本并冻结人工标注校准集，至少覆盖：

- 禁止主张被肯定发布；
- 用户原话复述、引号、问题转述；
- `未覆盖/无法确认/尚无证据` 的跨短句否定；
- 双重否定和转折后的真实肯定；
- 列表项、段落、句子内的局部引用；
- 只有资料附录引用、但正文主张未绑定；
- 固定政策拒答、通用明确拒答、证据不足的合理限制；
- 状态/处置与正文矛盾。

否定识别以语义单元、引号范围、说话者归属、转折边界和否定作用域共同判定，不再使用单一固定前窗。引用支持要求 concept 与有效引用出现在同一列表项或同一主张单元，资料来源附录不算正文支持。合理拒答必须同时满足：明确边界、未输出危险操作、说明证据/风险原因，并提供替代或升级路径；不能只凭 `policyDisposition` 通过。

评分器门禁：人工校准集不得有危险肯定假阴性；否定/复述假阳性为 0；引用绑定和合理拒答标签与人工标注一致率不低于 99%。评分器版本、校准集哈希和判定明细必须写入终验报告。

## 17. 测试策略

所有实现遵循 TDD：先写失败测试并确认失败，再做最小实现。

平台局部测试至少包括：

- 全新复合问法被拆成稳定原子义务，三次模型分类变化不改变 seed 数和跨度；
- 义务分别属于两个域时，三次均执行双域，主 scope 不裁域；
- 安全同义改写、语序变化和隐含目的走固定四段拒答；语义分类超时也不进入检索；
- `planner.compile`、检索、草稿、verifier 注入慢响应时按阶段截止降级，后续保留预算不被占用；
- 新链路检索不调用模型选择工具动作，且每个必答义务都获得独立候选与读页机会；
- 无引用、错域引用、未读引用、尾部集中引用和跨义务引用被程序删除；
- 全义务完成必为 answered，真实缺口才 partial/not_covered，内部候选未读不改变完成义务；
- 普通知识题模型开放式调用数满足上限；高风险题没有多数投票和最好答案选择；
- 高风险 verdict 不一致时不发布风险主张；一致且 direct 证据充分时发布；
- 缓存键随代码、任一知识修订、政策和 catalog 变化而失效；不合格答案永不写缓存；
- 冷运行报告拒绝任何 cache hit；三轮运行身份漂移直接失败；
- 评分器正确识别否定、引号、复述、引用局部性和通用拒答。

阶段级验证依次运行局部 Vitest、`npm test`、`npm run typecheck` 和 `npm run build`。提交前检查 diff 和工作树，只暂存本阶段文件。

## 18. 第四套全新百题冷运行

第三套百题从本设计批准后永久降为开发诊断集。第四套题只能在平台代码、评分器和配置冻结后创建，必须：

- 恰好 100 题，专业、通用、混合域、多轮、证据不足、安全边界各不少于 10 题；
- 与所有历史 e2e、regression、答案卡标准问法和前三套百题做规范化哈希排重；
- 额外做实体、动作、约束和交付目标组合的语义去重，不能只换同义词；
- 在首次运行前记录题集 SHA-256、历史排除集 SHA-256、代码提交、模型名、知识修订、评分器版本和 cacheMode；
- 每题独立调用三次，共 300 次，不挑最好输出、不边测边改；
- 首轮计算泛化指标，三轮计算链路可用性和结论一致性；
- 原始 observation、诊断摘要、round hash 和 final-report hash 全部冻结；
- 任一硬门槛失败就明确结论“未达到企业级验收”。

第四套题首次运行后立即视为已污染开发集。即使只差一题，也不能修改后继续用同一套宣称独立终验通过。
