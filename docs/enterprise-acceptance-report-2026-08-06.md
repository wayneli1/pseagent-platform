## 实际执行流程

每个问题均按以下粒度独立闭环：

1. 调用真实 `pse_answer` 接口测试一道题。
2. 失败时只为该问题在修订工作台生成一个草稿。
3. 对该草稿执行证据、必答项、安全、回归、发布就绪五类验证。
4. 仅将该草稿组成一个单项发布批次。
5. 20 道题只作为该单项发布前的全局安全门；任一回归失败即保留旧版本，不写入 Git。
6. 发布成功后同步 GitHub、激活新 Knowledge Engine 版本，再调用真实接口进行线上复测和独立复核。

## 缺陷分析与修复

### 验收脚本和复核器过严造成的误报

1. 发布后脚本把对外脱敏后的答案卡哈希 ID 与内部明文 ID 直接比较，导致实际命中被判失败；现已按真实 API 契约校验哈希值。
2. 脚本对空白、固定 RTO/固定恢复时长等同义表达逐字匹配，造成语义正确但验收失败；现已规范化空白并补充经过审查的等价表达。
3. 独立复核器曾要求一个必答项候选词列表中的每个词都逐字出现，而该列表实际是可表达同一事实的候选概念集合；现由确定性守卫只拦截“该必答项没有任何具体概念存活”的答案，完整性继续交由独立模型的 obligation checks 判断。

### 真实处理逻辑缺陷

1. 已从正式证据补入的必答概念，可能在模型验证阶段再次被随机删除；现会在模型验证后重新应用“已由本次读取证据逐字证明”的概念，同时不会补入无证据内容。
2. 答案卡必答项匹配曾出现只保留其中一个概念、追问别名未生效、问题族命中但遗漏回答卡要求等问题，均已补充确定性处理与测试。
3. 证据补全路径曾可能超时，已修复超时处理并保持安全失败策略。
4. 独立复核器把窄范围追问扩大成整张答案卡检查，例如只问后台侧却强制要求 PC 侧内容；现按本轮问题范围复核。
